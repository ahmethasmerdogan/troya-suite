# CLAUDE.md — Troya Modern Biletleme Platformu

IATA Ticketing Handbook'tan türetilen full-stack biletleme platformu. **Plan:** `TROYA_ETICKET_ROADMAP.md`. **Mimari:** `docs/ARCHITECTURE.md`. **Arayüz tasarımı:** `docs/DESIGN_ROADMAP.md`. **Görsel tasarım dili:** `docs/DESIGN_SYSTEM.md`. **Sözlük:** `docs/GLOSSARY.md`. Bu dosya senin (Claude Code) çalışma kurallarındır.

## Ne inşa ediyoruz
Bir PSS'in **elektronik biletleme modülü**: bilet (ET) ve EMD kesimi, **kupon yaşam döngüsü**, ET kaydının tam audit'i, search/display, exchange/reissue/refund/void, interline mesajlaşma. Troya'nın kriptik terminal ekranının yerine **tıklama-tabanlı React arayüzü**. **Order-native** düşünülür (gelecekte ONE Order). Kapsam DIŞI (port arkasında mock): inventory, availability, shopping, pricing engine, PNR, DCS, loyalty, revenue accounting.

İki track: **Engine (backend)** + **Experience (frontend)**. Temel ilke — **"tek komut, iki yüzey":** terminal komutu da React tıklaması da aynı backend komutuna map olur.

## Monorepo
```
backend/    Kotlin çok-modüllü: domain, application, infrastructure, api
frontend/   Vite + React + TypeScript
contracts/  OpenAPI spec — tek doğruluk kaynağı; TS tipi üretir
docs/       ARCHITECTURE.md, GLOSSARY.md, DESIGN_ROADMAP.md
```

## Backend mimari kuralları (ihlal etme)
1. **Event Sourcing.** State event'lerden türetilir; her değişiklik bir immutable, append-only domain event üretir. Audit trail domainin tanımı.
2. **CQRS.** Yazma (komut→aggregate→event) ve okuma (read model) ayrı. Komut tarafında sorgu için read model kullanma; aggregate'i rehydrate et.
3. **Coupon Status = explicit FSM.** Geçişler `CouponStatus`'te tanımlı; izin verilmeyen geçiş exception fırlatır. Final statüler (`E F G R V P X Z T`) terminal. Önce testi yaz.
4. **Hexagonal.** `domain` modülü framework/DB/Kafka bilmez. Dış sistemler port + adapter.
5. **Idempotency.** Para/statü değiştiren her komut idempotency key alır; tekrar = aynı sonuç, yan etki yok. Çift-issue/çift-refund kesinlikle olmaz.
6. **Outbox pattern.** DB transaction + mesaj yayını atomik. Doğrudan publish etme.
7. **Control invariant.** Kupon control'ünü aynı anda tek carrier tutar; sadece Validating Carrier grant/revoke eder; TTL'li lease (Redis).

## Frontend mimari kuralları
8. **Sunum adaptörü.** Frontend'de iş kuralı yok; backend otorite. Client-side validation (Zod) sadece hızlı geri bildirim.
9. **Para işleminde optimistic UI YOK.** Issue/exchange/refund/void sunucu sonucunu bekler ve doğrular; frontend idempotency key üretir (çift-submit koruması).
10. **Görsel-öncelikli state.** Kupon statüsü renk kodlu badge; yaşam döngüsü event timeline (history endpoint'i besler).
11. **Hibrit etkileşim.** Tıklama akışları + command palette (Cmd+K) ile uzman hızı.
12. **Type-safety (uçtan uca).** OpenAPI spec → TS tipleri (`openapi-typescript`); kontrat derlemede zorlanır. Elle tip yazma; üret.
13. **Gerçek zamanlı.** Statü/control değişiklikleri SSE/WebSocket ile UI'a yansır.

## Teknoloji
**Backend:** Kotlin + Spring Boot 3 (Java 21) · PostgreSQL 16 (event store + read model, `jsonb`) · Kafka/Redpanda · Redis · OpenAPI · SSE/WebSocket · JUnit 5 + Testcontainers + Kotest · OpenTelemetry · ktlint + detekt.
**Frontend:** Vite + React 18 + TypeScript · TanStack Router + Query · Zustand · React Hook Form + Zod · shadcn/ui + Tailwind · cmdk · TanStack Table · react-oidc-context · Vitest + RTL + Playwright.
**Ortak:** Docker Compose (Postgres + Redpanda + Redis + Keycloak).

## Çalışma yöntemi
- **Dikey dilim dilim.** Engine fazının API'sini stabil et, sonra FE dilimini yap (ya da Faz 0/1 temelinden sonra tandem). Yatay katman katman değil.
- **Test-first**, özellikle: state machine (tüm geçerli + geçersiz geçişler), idempotency, exchange/refund/void; frontend için Playwright e2e.
- **Küçük, cerrahi değişiklik.** İstenmeyen refactor yok; mevcut yapıyı bozma. Değiştireceksen önce nedenini söyle.
- **Domain dilini koru** (sözlük: `docs/GLOSSARY.md`): Ticket, Coupon, CouponStatus, Validating/Marketing/Operating Carrier, Airport Control, EMD, Fare Calculation, TFC.
- **Arayüz tasarımı:** görsel kararlar `docs/DESIGN_SYSTEM.md`'de (tek accent = mavi `#2563EB`; pill/two-tone/skeleton/dark-toast; shadcn-first). IA, ekran ve etkileşim kararları `docs/DESIGN_ROADMAP.md`'de — verildi. Status → `.pill` mapping `DESIGN_SYSTEM §9.1`. Orada da yoksa varsay, ne varsaydığını söyle.
- **Her faz sonunda** `docker compose up` + tüm testler yeşil; olmadan ilerleme.
- **Belirsizlik:** ROADMAP'teki handbook bölümüne (Ch x.y) referans ver.
